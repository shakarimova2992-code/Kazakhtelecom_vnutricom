# ЕСТЬ КОНТАКТ! / Байланыс БАР!

Корпоративный портал для подачи и модерации новостей от сотрудников.
Одностраничный сайт (RU/KZ), без сборки — чистые HTML/CSS/JS.

## Возможности

- Форма подачи новости из 5 вопросов + прикрепление фото/видео (лимит 200 МБ).
- Автоматическая сборка чернового поста в корпоративном стиле (душевно, лаконично).
- Личный кабинет источника новости: приветствие по имени, счётчики заявок.
- Панель модератора: лента заявок, фильтры по статусу, генерация/редактирование
  поста, публикация или отклонение.
- Полный интерфейс на русском и казахском языках (переключатель в шапке).
- Корпоративная стилистика: синий/белый/серый, тема «сигнал/соединение».

## Структура проекта

```
est-kontakt/
├── index.html          — разметка всех экранов (single page app)
├── css/styles.css      — все стили

```

## Быстрый локальный запуск

Открыть `index.html` напрямую в браузере — сайт полностью статический
и не требует сервера или сборки. Либо, для корректной работы некоторых
браузерных ограничений:

```bash
cd est-kontakt
python3 -m http.server 8080
# затем открыть http://localhost:8080
```

## Деплой на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него содержимое папки `est-kontakt/`.
2. В репозитории: **Settings → Pages → Source** → выберите ветку `main` и папку `/ (root)`.
3. Через минуту сайт будет доступен по адресу
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Никаких переменных окружения или ключей для базового (демо) режима не требуется.

## ⚠️ Важные ограничения демо-версии

Это полностью рабочий фронтенд, но **без сервера** данные видит только тот
браузер, в котором их подали:

- Заявки, счётчики и статусы хранятся в `localStorage` — они не появятся
  у модератора, если он открывает сайт с другого компьютера.
- Файлы (фото/видео) не сохраняются между визитами: для предпросмотра во
  время текущей сессии используется временная ссылка на файл в браузере,
  но не постоянное хранилище.
- Пароль модератора (`kt2026`) захардкожен в `js/app.js` — только для демо.

Для реальной эксплуатации (сотрудники по всей компании → один модератор,
видимый всем) нужен настоящий бэкенд с базой данных и файловым хранилищем.

## Подключение реального бэкенда (Firebase)

В `js/dataStore.js` уже заложена архитектура-адаптер: весь остальной код
обращается только к объекту `DataStore`, а не напрямую к localStorage.
Чтобы перейти на Firebase:

1. Создайте проект на [Firebase Console](https://console.firebase.google.com),
   включите **Firestore Database** и **Storage**.
2. В `index.html` перед `js/app.js` подключите SDK:
   ```html
   <script src="https://www.gstatic.com/firebasejs/10.7.0/firebase-app-compat.js"></script>
   <script src="https://www.gstatic.com/firebasejs/10.7.0/firebase-firestore-compat.js"></script>
   <script src="https://www.gstatic.com/firebasejs/10.7.0/firebase-storage-compat.js"></script>
   ```
3. В `js/dataStore.js` заполните `FirebaseAdapter.firebaseConfig` данными
   вашего проекта и раскомментируйте тела методов (`init`, `addSubmission`,
   `listSubmissions`, `getSubmission`, `updateSubmission`, `counts`).
4. В конце файла замените:
   ```js
   DataStore.useAdapter("local");
   ```
   на
   ```js
   DataStore.useAdapter("firebase");
   ```
5. Для загрузки самих файлов (200 МБ) в `submitWizard()` (`js/app.js`)
   вместо сохранения только метаданных нужно будет заливать файлы в
   Firebase Storage и сохранять в заявке готовые URL.

Firestore + Storage — рекомендованный вариант, потому что не требует
писать и поддерживать собственный сервер; но подойдёт и любой другой
бэкенд (Supabase, собственный REST API) — интерфейс `DataStore` останется
таким же.

Для реальной авторизации модератора и сотрудников вместо пароля/localStorage
рекомендуется Firebase Authentication (или корпоративный SSO), с правилами
доступа Firestore (Security Rules), ограничивающими запись/чтение по ролям.

## Подключение настоящего ИИ для генерации поста

Сейчас `js/postGenerator.js` собирает пост по шаблону — без вызова
внешней модели, поэтому он **не переводит** текст между языками, а только
оборачивает слова сотрудника в стилистическую рамку.

Чтобы получать настоящую стилизацию и перевод текста через Claude,
секретный API-ключ нельзя класть в клиентский JS (его украдут) — нужна
небольшая серверная функция-прокси (например, Cloudflare Worker,
Firebase Cloud Function или Vercel Serverless Function), которая:

1. Принимает от сайта JSON с ответами сотрудника.
2. Делает запрос к `https://api.anthropic.com/v1/messages` с вашим ключом
   (хранится в секретах сервиса, а не в коде).
3. Возвращает готовый текст поста на сайт.

Пример системного промпта для такой функции:

```
Ты — редактор корпоративных новостей компании. Стиль: душевно,
непринуждённо, но лаконично и понятно. Из ответов сотрудника собери
короткий пост (5-8 предложений) сначала на русском, затем отдельно —
на казахском (это должен быть настоящий перевод по смыслу, а не
дословный). Не выдумывай факты, которых нет в ответах.
```

После появления такой функции в `js/postGenerator.js` вместо шаблонной
сборки останется просто сделать `fetch("/api/generate-post", {...})`
и передать ответ модератору для финальной проверки — она в любом случае
рекомендуется перед публикацией.

## Логотип компании

`assets/logo-placeholder.svg` — это временная заглушка (стилизованный
знак «соединения», а не официальный логотип Kazakhtelecom). Точный
файл бренд-логотипа не воспроизведён намеренно — он является товарным
знаком компании и должен браться из официального брендбука. Перед
публичным запуском замените этот файл на официальный SVG/PNG-логотип —
достаточно сохранить его под тем же именем (`assets/logo-placeholder.svg`)
или поменять путь в `index.html` (`<img src="assets/...">` в шапке).

## Переводы на казахский язык

Тексты интерфейса на казахском (`js/i18n.js`, объект `I18N.kk`) подготовлены
как рабочий вариант. Перед официальным запуском рекомендуем вычитку
корпоративным переводчиком или носителем языка — особенно для брендовых
формулировок и тона.
